## 2026-10-05: Stage 2 - contracts and server validation

- Implemented only `API/job-posting-api/02-contract-and-validation.md`, after reading the shared requirements/review and inspecting the completed foundation. No applicable repository AGENTS.md was found. Preserved unrelated Angular Material work.
- Added nullable create DTO (missing/null salaries remain distinct from zero), immutable normalized payload, complete saved record with supplied UUID/UTC creation time, and the top-level accepted response with the agreed stable status/message. Contract construction does not claim persistence or publication.
- Added strict JSON reader rejecting malformed/root/type/calendar-date/overflow input with safe 400 errors. Missing/null fields pass to semantic validation rather than acquiring defaults. Duplicate, unknown and case-variant field names are rejected; unknown submitted names/values are not echoed. Invalid UTF-16 surrogate escapes are safely rejected as 400, including invalid property names; an additional regression check caught and corrected their initial InvalidOperationException escape.
- Added independent trimmed text validation (200/100/100/10000 UTF-16 units), decimal salaries 0–999999999.99 with maximum two places and strict min < max, and required closing date. Preserved description's internal whitespace/newlines and plain text. No floats, HTML transformation or inferred currency.
- Checked salary precision on original JSON tokens independently of decimal conversion, preventing tiny fractions from being accepted after rounding/underflow. Supported exact exponent encodings via effective decimal scale; documented that redundant third places such as 10.000 remain a 422 precision error, while 10 and 10.00 are equivalent. Wrong numeric types/overflow are 400; semantic precision/range/order are 422.
- Added single-value opaque idempotency header validation (1–128 ASCII letters/digits/underscore/hyphen), without generating a fallback or implementing the ledger. Added safe ValidationProblemDetails and top-level 409/503 code contracts; Retry-After/status/content type remain the future endpoint's responsibility.
- Added version-1 SHA-256 fingerprints over fixed-order UTF-8 JSON arrays containing all seven normalized fields, invariant two-place decimal strings and date-only formatting. Tests prove equivalent numeric/property-order/trimmed encodings match, all changed fields affect the digest, delimiter/Unicode content remains unambiguous and en-US/fr-FR/tr-TR/ar-SA do not alter fingerprints.
- Kept temporal validation separate from parsing/normalization/fingerprinting: injected clock plus configured business timezone validates future closing dates only for new keys, allowing later replay/resumption before changed-date checks. Tests cover Toronto midnight in winter/summer, leap day, expired dates and UTC clocks; prior startup invalid-timezone tests remain passing.
